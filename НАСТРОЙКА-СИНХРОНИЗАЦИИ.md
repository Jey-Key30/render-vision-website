# Настройка автосинхронизации — пошагово

Цель: сделать так, чтобы данные твоих работ (названия, годы, софт, описания, превью)
сами забирались с ArtStation и попадали на сайт. Один раз настроил — дальше работает без тебя.

Почему нельзя проще: ArtStation не разрешает браузеру обращаться к своим данным напрямую
(защита от чужих сайтов). Запрос должен идти с сервера. Бесплатный сервер для этого —
GitHub Actions: он принадлежит GitHub, работает по расписанию, платить не нужно.

Всего шагов шесть. Ничего устанавливать не надо, всё делается в браузере.
Ориентировочно 15 минут.

---

## Шаг 0. Что понадобится

- Аккаунт на GitHub. Репозиторий `Jey-Key30/render-vision-website` уже существует —
  значит аккаунт есть, войди в него.
- Архив проекта, который я присылал в чате. Скачай и распакуй его в любую папку.
  Внутри должны быть папки `site`, `sync`, `.github` и несколько файлов.

Если архива нет — скажи в чате, пришлю заново.

## Шаг 1. Открой репозиторий

Перейди по адресу:

    https://github.com/Jey-Key30/render-vision-website

Ты должен увидеть страницу репозитория. Сейчас в нём почти пусто — только `README.md`.
Если видишь ошибку 404, значит ты не вошёл в аккаунт — нажми **Sign in** сверху справа.

## Шаг 2. Загрузи файлы сайта

1. На странице репозитория найди кнопку **Add file** (сверху справа, рядом с зелёной
   кнопкой `Code`). Нажми её.
2. В выпадающем меню выбери **Upload files**.
3. Откроется страница с большой пунктирной областью и надписью
   «Drag files here to add them to your repository».
4. Открой рядом папку с распакованным архивом.
5. Выдели в ней папки `site` и `sync`, а также файлы `artstation-sync.md` и `github.md`.
   Перетащи их мышкой в пунктирную область на странице GitHub.
6. Подожди. Файлов около двадцати, плюс видео шоурила на несколько мегабайт —
   загрузка займёт полминуты-минуту. Под областью появится список загруженных файлов.
7. Прокрути страницу вниз. Там поле **Commit changes** с текстом по умолчанию
   «Add files via upload» — его можно не менять.
8. Нажми зелёную кнопку **Commit changes**.

Тебя вернёт на страницу репозитория, и там теперь будут видны папки `site` и `sync`.

**Важно:** папку `.github` из архива перетаскивать не нужно. Имена, начинающиеся с точки,
браузер считает скрытыми и часто их пропускает. Её создадим вручную на следующем шаге.

---

## Шаг 3. Создай файл автозапуска

Это инструкция для GitHub: что запускать и когда.

1. На странице репозитория снова нажми **Add file**, но теперь выбери
   **Create new file**.
2. Сверху появится поле для имени файла с подсказкой `Name your file...`.
   Впиши туда ровно это, вместе со слэшами:

       .github/workflows/sync-portfolio.yml

   По мере ввода слэшей GitHub сам будет создавать вложенные папки — увидишь, как имя
   разбивается на части. Это нормально, так и должно быть.

3. В большое поле ниже (редактор кода) вставь текст целиком:

```yaml
name: Sync portfolio from ArtStation

on:
  schedule:
    - cron: "0 5 * * *"
  workflow_dispatch:

permissions:
  contents: write

jobs:
  sync:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20

      - name: Run sync
        run: node sync/sync.mjs --thumbs

      - name: Commit if changed
        run: |
          git config user.name "portfolio-sync"
          git config user.email "actions@github.com"
          git add site/data/portfolio.json site/assets/thumbs
          if git diff --cached --quiet; then
            echo "no changes"
          else
            git commit -m "sync: portfolio data $(date -u +%Y-%m-%d)"
            git push
          fi
```

4. Прокрути вниз, нажми зелёную **Commit changes**.
5. Появится окошко с полем для описания — просто нажми **Commit changes** ещё раз.

Отступы в этом файле важны: YAML понимает структуру по пробелам. Поэтому копируй
блок целиком, не переписывай руками.

## Шаг 4. Разреши записывать результат

Скрипт не только читает ArtStation — он сохраняет результат обратно в репозиторий.
По умолчанию GitHub это запрещает, и без этого шага прогон упадёт на последней строчке.

1. В репозитории открой вкладку **Settings** (самая правая в ряду вкладок сверху:
   Code, Issues, Pull requests, Actions, Projects, Wiki, Security, Insights, Settings).
2. В левом меню найди раздел **Actions**, нажми и выбери подпункт **General**.
3. Прокрути страницу вниз до блока **Workflow permissions**.
4. Там два варианта с кружками. Выбери **Read and write permissions** (по умолчанию
   стоит «Read repository contents and packages permissions»).
5. Нажми **Save** под этим блоком.

---

## Шаг 5. Запусти синхронизацию

1. Вернись в репозиторий и открой вкладку **Actions**.
2. Если увидишь большую надпись про то, что workflows отключены, и жёлтую кнопку —
   нажми **I understand my workflows, go ahead and enable them**.
3. В левой колонке появится пункт **Sync portfolio from ArtStation**. Нажми на него.
4. Справа будет серая плашка с текстом «This workflow has a workflow_dispatch event
   trigger» и кнопка **Run workflow**. Нажми её, затем в выпавшем окошке —
   зелёную **Run workflow**.
5. Обнови страницу через несколько секунд. В списке появится строка с жёлтым кружком —
   прогон идёт. Через одну-две минуты кружок станет зелёной галочкой.

Зелёная галочка означает: данные забраны с ArtStation, файл `site/data/portfolio.json`
перезаписан, превью работ скачаны в `site/assets/thumbs/`.

---

## Шаг 6. Проверь результат

Открой в репозитории файл `site/data/portfolio.json`. В самом начале будет блок `source`
с полем `syncedAt` — там должна стоять сегодняшняя дата и время прогона. Ниже в списке
`projects` у работ появятся настоящие описания, годы и теги вместо пустых полей.

Скажи мне в чате, что прогон прошёл — я заберу обновлённый файл из репозитория в наш
проект, и посмотрим на сайт с реальными работами.

## Если прогон упал с ошибкой 403

```
Error: 403 https://www.artstation.com/users/j-k30/projects.json
```

Это не поломка скрипта. ArtStation стоит за Cloudflare, и тот отклоняет запросы с
IP-адресов дата-центров. Серверы GitHub Actions — как раз дата-центр, поэтому их
блокируют независимо от того, что и как запрашивать. С домашнего интернета тот же
запрос обычно проходит.

Скрипт я поправил: теперь он на 403 не падает. Прогон в Actions продолжит работать и
будет обновлять то, что доступно — модели с Sketchfab, полигонаж, превью моделей и
видео с YouTube-канала. Данные ArtStation в этом случае берутся из последнего удачного
прогона и не теряются.

Чтобы забрать данные ArtStation, синк нужно один раз запустить у себя:

1. Установи Node.js 20 с nodejs.org (кнопка LTS), если его нет.
2. Распакуй архив проекта, открой папку с ним.
3. Открой в этой папке терминал. На Windows: щёлкни правой кнопкой по пустому месту
   в папке при зажатом Shift → «Открыть окно PowerShell здесь». На macOS: правой
   кнопкой по папке → «Службы» → «Новый терминал в папке».
4. Выполни:

       node sync/sync.mjs --thumbs

5. В консоли пойдут строки `· ok Название работы`. По окончании файл
   `site/data/portfolio.json` будет перезаписан, а превью лягут в `site/assets/thumbs/`.
6. Загрузи обновлённые `site/data/portfolio.json` и папку `site/assets/thumbs` в
   репозиторий тем же способом, что в Шаге 2. Либо пришли `portfolio.json` мне в чат.

Дальше ночная автосинхронизация в Actions будет поддерживать актуальность Sketchfab и
YouTube, а данные ArtStation обновляются локальным прогоном, когда выкладываешь новые
работы. Это редкая операция, поэтому годится.

## Если что-то пошло не так

**Красный крестик вместо галочки.** Нажми на строку прогона, затем на шаг с красным
значком — раскроется лог. Скопируй последние строк десять и пришли мне в чат.
По тексту ошибки я пойму, в чём дело, и поправлю скрипт.

Частые причины:

- *403* на запросах к ArtStation — IP заблокирован Cloudflare. Разбор выше, в разделе
  «Если прогон упал с ошибкой 403».
- *Permission denied* или *403* на шаге «Commit if changed» — не сделан Шаг 4.
- *no ArtStation projects returned* — неверный username. Проверь: в адресе твоего
  профиля `artstation.com/j-k30` последняя часть и есть username. Он записан в файле
  `sync/config.json`, поле `artstation`.
- *404* на запросах — ArtStation поменял адреса своих эндпоинтов. Такое бывает,
  это правится с моей стороны.

**Прогон идёт больше пяти минут.** С флагом `--thumbs` скрипт скачивает превью всех
работ, на большом портфолио это долго. Подожди, но если висит больше десяти минут —
напиши.

## Что будет дальше

Каждую ночь в 05:00 UTC (08:00 по Москве) GitHub сам запустит скрипт. Если ты выложил
новую работу на ArtStation — она появится на сайте к утру. Если ничего не менялось,
прогон отработает впустую и ничего не закоммитит.

Кнопка **Run workflow** остаётся: когда нужно обновить сайт сразу, не дожидаясь ночи.

Ручные правки, которых нет на площадках — точное число полигонов, своя формулировка
описания, свой порядок медиа — пишутся в файл `sync/overrides.json`. Они перекрывают
данные с ArtStation и не теряются при прогонах. Формат я оставил в самом файле примером.

# Синхронизация данных — ArtStation, Sketchfab, YouTube

Сайт не хранит контент в разметке. Он читает один файл:

    site/data/portfolio.json

Этот файл генерируется скриптом `sync/sync.mjs`. Если fetch не удался, страница
показывает `SYNC FAILED · NO DATA` и остаётся рабочей.

## Запуск

Нужен Node 18+ (в нём есть встроенный `fetch`), зависимостей нет.

```bash
node sync/sync.mjs              # обычный прогон, перезаписывает portfolio.json
node sync/sync.mjs --dry        # вывести результат в консоль, ничего не писать
node sync/sync.mjs --thumbs     # ещё и скачать превью в site/assets/thumbs
node sync/sync.mjs --limit 12    # ограничить число проектов
```

## Настройка — `sync/config.json`

| поле | что это |
| --- | --- |
| `artstation` | username профиля, например `j-k30` из `artstation.com/j-k30` — единственное обязательное поле |
| `sketchfab` | username на Sketchfab; модели подтягиваются через публичный API v3, ключ не нужен |
| `youtubeChannelId` | ID канала (`UC...`); читается публичный RSS-фид, ключ не нужен |
| `reel` | видео для блока Showreel; если пусто — берётся последняя загрузка с канала |
| `defaults` | чем заполнять `role` / `software` / `tris`, когда площадка их не отдаёт |
| `limit` | максимум проектов |

## Откуда что берётся

**ArtStation** — основной источник. Скрипт использует те же публичные JSON-эндпоинты,
которыми пользуется сам сайт artstation.com:

- `artstation.com/users/{user}/projects.json?page=N` — список работ,
- `artstation.com/projects/{hash_id}.json` — детали: описание, теги, софт, ассеты.

Из ассетов собираются медиа-блоки проекта. Важное: если внутри работы на ArtStation
вставлен плеер YouTube или вьюер Sketchfab, скрипт вытаскивает `videoId` и `modelId`
прямо из кода эмбеда — то есть видео и 3D приходят автоматически, без ручного ввода.

**Sketchfab** — публичный поиск по твоему username. Модель привязывается к проекту по
совпадению названий (нужно ≥50% общих слов). Оттуда же берётся `faceCount` в поле `tris`.

**YouTube** — RSS-фид канала. Работает так же: видео цепляется к проекту по названию,
а первая загрузка становится шоурилом, если `reel.videoId` не задан.

**Теги и фильтры.** Теги ArtStation, категории и описание прогоняются через словарь
`buckets` (его можно переопределить в config) и раскладываются по четырём кнопкам:
`HARD-SURFACE`, `ENVIRONMENT`, `VFX / SIM`, `GAME-READY`.

## Ручные правки — `sync/overrides.json`

Файл с объектами по ключу `id` проекта (slug из названия). Любое поле оттуда
перекрывает синхронизированное. Так дописывают то, чего на площадках нет: точное
количество трисов, роль в проекте, свой порядок медиа, отдельная модель Sketchfab.
Правки не теряются при следующем прогоне.

## Автообновление

`.github/workflows/sync-portfolio.yml` запускает скрипт раз в сутки (05:00 UTC) и по
кнопке Run workflow. Если JSON изменился — коммитит его в репозиторий. При хостинге на
Vercel / GitHub Pages деплой поднимется сам. Тот же скрипт ставится на любой cron:
`node sync/sync.mjs --thumbs`.

Из браузера напрямую эти запросы не сделать: ArtStation и YouTube не отдают CORS-заголовки,
поэтому синхронизация всегда серверная.

## Контракт JSON

Верхний уровень: `source`, `reel`, `projects`.

| поле проекта | назначение |
| --- | --- |
| `id` | стабильный slug, используется в URL проекта |
| `title`, `year`, `role`, `software`, `tris` | заголовок и мета-колонка |
| `topic` | надзаголовок на странице проекта |
| `tags` | фильтры по темам |
| `kindKey` | фильтр по типу медиа и бейдж на карточке (`IMAGE` / `VIDEO` / `YOUTUBE` / `SKETCHFAB`) |
| `slot` | подпись в пустой карточке, пока нет превью |
| `artstationUrl` | ссылка «VIEW ON ARTSTATION» |
| `summary` | описание на странице проекта |
| `media[]` | блоки по порядку: `{t: image, src}`, `{t: video, src}`, `{t: youtube, videoId}`, `{t: sketchfab, modelId}` |

## Что нужно от тебя

1. Username на ArtStation (сейчас в конфиге стоит `j-k30` — проверь).
2. Username на Sketchfab, если модели нужно тянуть автоматически.
3. ID YouTube-канала (`UC...`) — есть в исходном коде страницы канала.
